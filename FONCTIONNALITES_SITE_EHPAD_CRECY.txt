État du projet analysé au 20 août 2026


======================================================================
1. PRÉSENTATION GÉNÉRALE DU PROJET
======================================================================

Le site de l’EHPAD de Crécy-la-Chapelle n’est pas seulement un site vitrine. Il a été conçu comme un portail d’information et de services destiné aux futurs résidents, aux familles, aux proches, aux professionnels, aux candidats et aux équipes de l’établissement.

Ses objectifs principaux sont les suivants :

- présenter clairement l’établissement, ses valeurs, ses chambres et ses équipes ;
- rassurer les familles et faciliter la préparation d’une admission ;
- rendre les tarifs et les aides financières compréhensibles ;
- valoriser la vie sociale, les activités et les événements ;
- permettre aux proches d’envoyer facilement une carte à un résident ;
- publier les actualités, les photographies et le journal de l’établissement ;
- faciliter le recrutement des quatre EHPAD placés en direction commune ;
- donner aux agents autorisés des outils simples pour mettre à jour le contenu ;
- garantir un niveau élevé d’accessibilité, de sécurité et de performance ;
- assurer la continuité du service grâce aux sauvegardes, aux tests et à la supervision.

L’identité visuelle repose sur une présentation chaleureuse, moderne et institutionnelle, avec des couleurs adaptées, des cartes illustrées, des dégradés, des animations mesurées et une mise en page responsive pour ordinateur, tablette et téléphone.

Le site présente notamment l’EHPAD comme un établissement public de 63 places, implanté à Crécy-la-Chapelle en Seine-et-Marne, habilité à l’aide sociale et proposant des chambres simples et doubles.

======================================================================

6.1. Tarifs publiés

Les tarifs en vigueur depuis avril 2026 sont centralisés dans une source unique afin d’éviter les incohérences entre les pages.

Le site présente :

- le tarif d’hébergement en chambre simple ;
- le tarif d’hébergement en chambre double ;
- le tarif applicable aux personnes de moins de 60 ans ;
- les tarifs dépendance par groupes GIR ;
- le ticket modérateur ;
- les prestations incluses ;

Les prestations incluses mentionnées comprennent notamment les repas, le linge de lit et de toilette, l’entretien du linge personnel, les protections, les soins assurés par les professionnels de l’établissement et les animations.

6.2. Simulateur de reste à charge

Un simulateur interactif permet d’obtenir une estimation personnalisée.

L’utilisateur peut choisir :

- le type de chambre ;
- le niveau de dépendance GIR ;
- la prise en compte ou non de l’APA.

Le simulateur calcule ensuite :

- le coût journalier d’hébergement ;
- le coût journalier lié à la dépendance ;
- le total journalier ;
- une estimation mensuelle du reste à charge.

Il s’agit d’une estimation pédagogique permettant aux familles de mieux comprendre la structure de la facturation avant de contacter l’établissement.

13. LE POSTIER NUMÉRIQUE
======================================================================

Le Postier numérique est l’une des principales fonctions de service du site. Il permet à un proche d’envoyer gratuitement une carte numérique à un résident.

13.1. Parcours de la famille

Le parcours a volontairement été maintenu très simple :

1. la famille saisit le code secret transmis pour le résident ;
2. le système vérifie le code sans révéler d’informations si celui-ci est incorrect ;
3. le proche indique son nom ;
4. il écrit son message ;
5. il peut ajouter une photographie facultative depuis son téléphone ou sa galerie ;
6. il envoie la carte ;
7. une confirmation indique que l’équipe imprimera et remettra la carte au résident.

La photographie est optimisée avant son envoi afin de réduire son poids.

13.2. Gestion par l’établissement

Dans l’administration, les agents autorisés peuvent :

- consulter les nouveaux courriers ;
- filtrer et sélectionner les messages ;
- visualiser le texte et la photographie ;
- imprimer une carte mise en page pour le résident ;
- marquer le courrier comme distribué ;
- supprimer un message ;
- supprimer plusieurs messages en une seule opération.

Lorsqu’un courrier est marqué comme distribué, sa photographie est supprimée afin de limiter la conservation des données. Les courriers distribués peuvent être purgés après une durée de conservation de 30 jours.

13.3. Gestion des résidents et des codes

L’administration permet :

- d’ajouter un résident ;
- d’indiquer sa chambre ;
- de générer automatiquement un code secret individuel ;
- de régénérer le code si nécessaire, ce qui invalide l’ancien ;
- de supprimer le dossier du résident ;
- de consulter la liste des codes à transmettre aux familles.

L’accès à ces fonctions est réservé aux comptes possédant le rôle administrateur.

14. FORMULAIRE DE CONTACT
======================================================================

Le formulaire de contact centralise plusieurs types de demandes :

- demande d’information générale ;
- programmation d’une visite ;
- dossier d’admission ou question sur les tarifs ;
- recrutement et candidature ;
- autre demande.

Le formulaire recueille le prénom, le nom, le courriel, le téléphone facultatif et le message. Une personne peut également demander à programmer une visite.

Pour une candidature, le formulaire s’adapte automatiquement :

- l’objet Recrutement est présélectionné ;
- l’offre et l’établissement concernés sont ajoutés à la demande ;
- le message est prérempli avec le titre du poste ;
- le candidat peut joindre un CV au format PDF, DOC ou DOCX ;
- la candidature est envoyée par le site, sans obliger le candidat à passer par la FHF.

Le formulaire utilise la gestion sécurisée des formulaires Netlify et comporte un champ anti-robots invisible qui ne complique pas le parcours humain.

15. RECRUTEMENT ET SYNCHRONISATION AVEC LA FHF
======================================================================

La page Recrutement présente les avantages de travailler dans la Fonction publique hospitalière et les offres de la direction commune.

Les quatre établissements distingués sont :

- EHPAD de Crécy – Crécy-la-Chapelle ;
- EHPAD Le Marais – La Ferté-Gaucher ;
- EHPAD Saint Aile – Rebais ;
- EHPAD Pierre Comby – Rozay-en-Brie.

15.1. Synchronisation automatique

Les offres publiées sur les pages FHF de ces quatre établissements sont synchronisées automatiquement une fois par jour.

L’établissement n’a aucune action manuelle à effectuer dans l’administration :

- une nouvelle annonce FHF apparaît automatiquement sur le site ;
- une annonce dont la date limite est dépassée est masquée ;
- une annonce retirée de la FHF disparaît après la synchronisation suivante ;
- si la FHF est temporairement inaccessible, la synchronisation échoue sans effacer volontairement la dernière liste connue.

Les données synchronisées sont conservées dans un stockage Netlify dédié, avec une copie locale de secours permettant de continuer à afficher les dernières offres disponibles.

15.2. Parcours de candidature maîtrisé par l’EHPAD

La FHF sert uniquement de source pour identifier les postes ouverts. Le visiteur reste sur le site de l’EHPAD pour consulter l’offre et postuler.

Le site ne met pas en avant les coordonnées ni le lien de candidature de la FHF. Le bouton « Postuler maintenant » ouvre le formulaire interne avec l’offre et l’établissement déjà identifiés.

Une candidature spontanée reste également possible.

15.3. Identification visuelle des quatre établissements

Chaque établissement possède une couleur avec dégradé :

- Crécy : rouge ;
- Le Marais / La Ferté-Gaucher : orange ;
- Saint Aile / Rebais : violet ;
- Pierre Comby / Rozay-en-Brie : vert.

Un filtre permet d’afficher tous les postes ou seulement les annonces d’un établissement.

17. ESPACE D’ADMINISTRATION
======================================================================

L’administration est protégée par Netlify Identity et par la vérification du rôle « admin ». Les contrôles sont effectués à la fois dans l’interface et dans les fonctions serveur.

Les sections disponibles sont :

- Photos ;
- Blog ;
- Écho du Cœur ;
- Résidents ;
- Courriers.

17.1. Gestion des photos

L’administrateur peut :

- créer un album avec un titre et une date ;
- ajouter plusieurs photographies en une seule sélection ;
- voir un aperçu avant publication ;
- modifier le titre d’une photographie ;
- ajouter les photographies à un album existant ;
- renommer un album ;
- sélectionner plusieurs photographies ;
- supprimer une photographie, une sélection ou un album ;
- suivre la progression d’un envoi en lot.

Les photographies sont compressées et des miniatures sont créées. Les envois multiples sont regroupés afin de limiter le nombre de déploiements Netlify.

17.2. Gestion du blog

L’administrateur peut :

- créer un article ;
- choisir sa date et sa catégorie ;
- ajouter et optimiser une image ;
- rédiger un résumé et le contenu ;
- enregistrer un brouillon ;
- publier un article ;
- modifier ou supprimer un article existant.

17.3. Gestion du Petit Écho du Cœur

Deux modes de publication sont disponibles :

- publication traditionnelle d’un PDF ;
- création d’une Gazette numérique directement dans le site.

L’éditeur de Gazette numérique permet :

- d’ajouter un sommaire automatique ;
- d’ajouter des titres et des paragraphes enrichis ;
- d’ajouter des photographies ;
- de placer une image au centre, à gauche ou à droite d’un texte ;
- de choisir des couleurs de fond ;
- de rechercher une illustration dans une banque d’images ;
- de créer une illustration avec l’outil d’intelligence artificielle Cloudflare lorsque le service est configuré ;
- de prévisualiser le résultat ;
- d’imprimer la Gazette ;
- de publier ou supprimer une édition.

Une image produite par intelligence artificielle n’est insérée qu’après validation humaine et reçoit automatiquement la mention « Illustration générée par IA ».

17.4. Gestion du Postier

L’administration regroupe la gestion des résidents, des codes secrets, des courriers reçus, de l’impression, de la distribution et de la suppression, comme décrit dans la partie consacrée au Postier numérique.

19. ACCESSIBILITÉ NUMÉRIQUE ET RGAA
======================================================================

L’accessibilité a été traitée comme une fonction centrale du projet et non comme un simple ajout visuel.

Le site publie :

- une déclaration d’accessibilité ;
- un rapport d’audit détaillé ;

L’audit interne RGAA 4.1.2 publié le 16 août 2026 déclare le site totalement conforme, avec 84 critères respectés sur 84 critères applicables, soit 100 % sur l’échantillon audité.

Les améliorations réalisées comprennent notamment :

- lien d’évitement vers le contenu principal ;
- titres et régions de page structurés ;
- navigation possible au clavier ;
- focus visible ;
- fermeture des fenêtres avec Échap ;
- noms accessibles pour les boutons ;
- états ARIA pour les menus, onglets, FAQ, formulaires et fenêtres ;
- messages d’erreur et confirmations annoncés aux lecteurs d’écran ;
- contraste renforcé ;
- fonctionnement vérifié avec un zoom à 200 % et 400 % ;
- mode d’affichage avec texte agrandi et contraste élevé ;
- mémorisation locale de la préférence d’affichage ;
- tests avec le lecteur d’écran NVDA sous Windows ;
- sous-titres et transcription de la vidéo ;
- alternative HTML pour la Gazette composée d’images ;
- lecteur PDF adapté aux limites d’iOS et d’Android ;
- respect de la préférence système de réduction des animations.

Une vérification VoiceOver sur Safari reste recommandée dans le cadre de l’amélioration continue, notamment après les évolutions importantes.

21. PERFORMANCE, ÉCOCONCEPTION ET SOBRIÉTÉ
======================================================================

Plusieurs travaux ont été réalisés pour rendre le site plus rapide et limiter son poids :

- conversion automatique des images vers des formats WebP et AVIF ;
- création de plusieurs tailles adaptées à la largeur de l’écran ;
- utilisation de miniatures dans la galerie ;
- chargement différé des médias lourds ;
- optimisation des photographies avant publication ;
- suppression des originaux inutiles dans le dossier final de déploiement, sans supprimer les sources de travail ;
- déduplication automatique des médias strictement identiques ;
- version vidéo spécifique plus légère pour les téléphones ;
- aperçu très léger du panorama 360 degrés avant son activation ;
- chargement de l’assistant complet uniquement lors de son ouverture ;
- chargement de Netlify Identity seulement sur les pages qui en ont besoin ;
- polices hébergées localement afin que le build ne dépende pas de Google Fonts ;
- cache longue durée pour les fichiers statiques optimisés ;
- budget automatique limitant la taille du JavaScript, du CSS, de la vidéo mobile, du panorama et de l’export global.

Ces optimisations améliorent le temps d’affichage, réduisent la consommation de données mobiles et limitent l’utilisation inutile des ressources Netlify.

22. SÉCURITÉ ET PROTECTION DES DONNÉES
======================================================================

Les mesures techniques comprennent :

- authentification Netlify Identity ;
- contrôle obligatoire du rôle administrateur sur les fonctions sensibles ;
- restriction des méthodes HTTP autorisées ;
- validation des corps JSON et limitation de leur taille ;
- contrôle des formats, dimensions et poids des images ;
- vérification de la signature réelle des fichiers PDF ;
- assainissement du HTML produit par l’éditeur de Gazette ;
- limitation des balises, attributs, couleurs et protocoles autorisés ;
- noms de commits techniques ne contenant pas les messages ni les noms des familles ;
- erreur générique en cas de mauvais code résident afin de limiter la recherche automatisée de codes ;
- suppression de la photographie du Postier après distribution ;
- possibilité de purger les courriers distribués après 30 jours ;
- journalisation technique des erreurs sans recopier le contenu personnel des messages ;
- politique de sécurité des contenus CSP ;
- protection contre l’intégration du site dans une fenêtre externe ;
- en-têtes contre la détection incorrecte des types de fichiers ;
- politique restrictive concernant caméra, microphone, géolocalisation, paiement et périphériques ;
- pages légales et politique de confidentialité ;
- absence de données médicales dans les contenus publics.

Le Postier ne comporte volontairement pas de CAPTCHA visible afin de conserver un parcours simple pour les familles. Les protections sont autant que possible techniques et invisibles.

24. SAUVEGARDE, DÉPLOIEMENT ET SUPERVISION
======================================================================

24.1. Sauvegarde et historique

Le dépôt GitHub constitue la source de référence du site. Il conserve :

- le code ;
- les pages ;
- les médias publiés ;
- les articles ;
- les données utilisées par l’administration et le Postier ;
- l’historique des modifications.

Chaque modification enregistrée crée une version récupérable. Une procédure documentée explique comment créer une sauvegarde datée, restaurer un fichier ou revenir proprement à une version saine sans effacer l’historique.

Les secrets techniques ne sont pas stockés dans GitHub. Ils restent dans les variables protégées de Netlify.

24.2. Déploiement

Le site est généré sous forme statique avec Next.js puis publié sur Netlify. Les fonctions nécessitant un traitement serveur sont exécutées par Netlify Functions.

Les mises à jour effectuées dans l’administration créent une modification du dépôt, puis Netlify reconstruit le site. Les envois de photographies en lot sont regroupés pour éviter de déclencher inutilement plusieurs builds.

Un déploiement direct depuis le poste de travail est également prévu afin de préserver le quota de minutes de build Netlify.

24.3. Supervision automatique

Un script contrôle les parcours essentiels de production :

- page d’accueil ;
- page Contact ;
- page Admissions ;
- page Administration ;
- page Familles ;
- état des fonctions serveur ;
- refus attendu d’un appel incorrect au Postier ;
- refus attendu d’un accès non authentifié à l’administration des courriers.

Les contrôles vérifient le code HTTP et la présence d’éléments attendus dans les pages. Un journal technique aide à diagnostiquer les erreurs sans enregistrer les données personnelles des familles.
